# Predeclared production equivalence protocol

This is a validation plan, not production extraction or acceptance. Recorded
before production branch creation and numerical execution. Research authority is
literal b961d20ce4a803e55336fb5590c30574e23b2fad. The official base must be fetched
and rechecked immediately before extraction; currently observed6a2900a is only a
planning input.

1. Copy the complete11module runtime closure from literal accepted Git objects
   only after W3 ACCEPT. Preserve module bytes except a documented narrow change
   of the actual optimizer provenance pin to the production base's gitlink.
   Preserve accepted-W2 attribution and every runtime/helper/version/source
   identity check. Record any other deliberate source difference separately.
2. Preserve every upstream existing node, publisher, launch, reader, message,
   map/config and recursive gitlink byte-for-byte. Add packaging/resources/CLI
   without deleting an existing script or stack_master dependency. Declare
   direct rclpy/geometry_msgs dependencies explicitly. Run no live nodes.
3. Generate actual source/build/lock/resource provenance in a staged package and
   perform an ordinary non-symlink install. Runtime imports must come solely from
   this prefix. The separate runtime has no source/build/research paths, network
   or unbounded writable filesystem.
4. Freshly compile S0, both selected S2 alternatives, S3 surfaces/notch and S6
   (.52m explicit mesh), under exact accepted fixture/model/policy bytes.
   Retain producer C before retiming and H after freezing; run real geometry and
   dynamics validation on persisted bytes under the separately retained H.
   Actual new implementation identity means new H is expected; no old-identity
   bypass or old-report authorization is permitted.
5. Compare these products against the independently authenticated final research
   campaign and, if necessary to distinguish host rounding, a controlled same-host
   accepted-code run. Compare exact input/model/footprint/policy and ownership;
   number/order of segments, profile knots and occurrence IDs; original q and
   coefficient arrays; actual speed/cap/profile/arc/time and cyclic acceleration;
   final geometry/dynamics PASS/coverage and actual nine-group ROS/CDR products.
6. For equivalent supported binary64 runs, predeclared floating comparison gates
   are abs1e-10m + rel1e-12 for coefficient/q/station/length values, abs1e-8s +
   rel1e-10 for nominal times, abs1e-8 + rel1e-10 for squared-speed/caps/profile,
   and abs1e-8 in the relevant units for public speed/acceleration/curvature.
   Integer/string topology, occurrence/surface ownership and categorical policies
   must match exactly. These are cross-run diagnostic comparison limits, not
   relaxed numerical solver/proof policies. Both sides must independently pass
   their original unchanged continuous proof policies and resource bounds.
   Any larger difference, changed iteration/segmentation or changed status must
   be diagnosed explicitly before acceptance; do not silently increase limits.
7. Use independent analytic/Decimal/Fraction oracles in the curated suite,
   particularly true arc, closing-edge acceleration, positive affine-u Q1,
   original q and continuous swept-footprint negatives. Both genuine validators
   must execute on valid persisted products and fresh failure must dominate an
   old PASS. Wrong external H, stale policy, authoritative content mutation,
   missing producer C and invalid swept geometry must reject for intended reasons.
8. Run actual current legacy checks against the authenticated6a baseline failure
   identities and complete1182 diagnostic multiset (requery if upstream changes).
   Separate current inherited failures from functional success. Do not embed
   large raw baseline logs in the lean branch merely to match old diagnostics.
9. S6 optional stress acceptance uses an explicit600second outer per-case budget
   including compile/reload/query/export, while retaining all original internal
   solver/point/condition/proof limits. Record actual wall/CPU/RSS scope; outer
   timings do not establish physical real-time suitability or whole-process-tree
   CPU/RSS unless those quantities are actually measured. Timeout is failed or
   inconclusive, with durable partial output. Retain .50conditioning and finer
   point-budget negatives. Full96 experiments stay in research archive.
10. After this succeeds, an isolated integration challenge must independently
    inspect missing dependencies/resources, omitted research imports, provenance,
    preserved upstream behavior, fail-closed artifacts and actual installed ROS
    serialization. Only then publish a reviewable upstream PR; never merge it.
